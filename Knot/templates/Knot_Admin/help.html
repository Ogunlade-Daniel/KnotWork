Quick Start Recommended first

Five steps from zero to a fully-configured Command Center.

Verify your admin identity

Enroll MFA and confirm your email. Root admins cannot be created without both.

Configure site identity

Set your name, logo, and support email under Settings → General.

Set commission & payouts

Choose your split, connect at least one payout provider, and set the payout window.

Invite your team

Assign roles carefully — the Editor role can publish, Moderator can flag, only Admin can pay out.

Run the health check

Open the System Health dock at the bottom of any admin page. All six tiles should read green.

Admin-only shortcut Press ⌘ + K anywhere in Command Center to jump straight to any admin page, user, course, or config key.

Command Center Overview

How the 16 admin surfaces fit together — and which ones need care.

The sidebar is organised into four families: Command (real-time telemetry), People (members, roles, invitations), Content (courses, moderation, finance), and System (audit, integrations, settings). Each family has exactly one root-only surface.

Live Pulse vs. Analytics Live Pulse is a streaming view of the last 15 minutes. Analytics is a 30-day aggregate. Both pull from the same warehouse, so numbers reconcile within 60 seconds.
  • Command Center — your daily driver: KPIs, pending actions, and a real-time activity feed.
  • Live Pulse — watch what's happening right now: signups, purchases, moderation flags, API errors.
  • Members — search, filter, suspend, or export any account across 12.4k users.
  • Roles & Permissions — create custom roles, grant granular scopes, audit every change.
  • Moderation — the flag queue. Median time-to-resolution is 14 minutes; aim to beat it.
  • Finance & Payouts — the only surface where money moves. Root-only by default.

Roles & Permissions Admin-scoped

Granular access control — who can do what, and how to change it safely.

Root

Knotwork ships with seven built-in roles. You can create custom roles but you cannot edit the built-ins — that's deliberate. Built-ins are audited once a quarter by an external firm.

  • Super Admin (Root) — full access including payouts, API keys, and danger zone.
  • Admin — everything except payout execution and API key rotation.
  • Finance — payouts, refunds, ledger only. No user or content access.
  • Moderator — flag queue, user suspensions, content takedowns.
  • Editor — publish and edit courses, announcements, email templates.
  • Support — read-only on users, tickets, and audit logs.
  • Analyst — read-only on all analytics surfaces.
Principle of least privilege Grant the smallest scope that lets someone do their job. You can always expand a role later; you cannot un-leak a credential.
roles.example.py 
# Grant a temporary finance role with a 90-day expiry.
from knotwork.auth import grant

grant(
    user='amara@knotwork.io',
    role='finance',
    scopes=['payouts.read', 'payouts.execute'],
    expires_in='90d',
)

Moderation Playbook

How to handle the three flag types without over-correcting.

Flags come in three severities. The median resolution is 14 minutes; the SLA is 4 hours for critical, 24 hours for medium, 72 hours for low. Every action you take is attributed to your admin ID.

Critical — remove immediately

Harassment, doxxing, or illegal content. Take the content down, suspend the account for 30 days, and file an incident note. Do not attempt to mediate.

Medium — investigate first

Plagiarism, misleading course claims, or repeated off-topic posts. Read the context, check the user's history, then decide.

Low — educate, don't punish

Formatting issues, minor policy edge cases, first-time mistakes. Reply with a link to the relevant policy and close the flag.

Pattern beats incident One flag is noise. Three flags on the same account in 30 days is a pattern — escalate to a manual review and add a private note.

Finance & Payouts Root-only

Where money leaves the platform — read this before you press anything.

Root

Payouts follow a four-state lifecycle: accrued → held → approved → settled. Accrued funds appear instantly in a mentor's ledger. Held funds sit through the hold period you configure. Approved funds are waiting for the provider. Settled funds have landed.

Irreversible Once a payout is marked settled, it cannot be reversed through Command Center. Refunds after settlement must go through the provider's dispute process and may take 30+ days.

Key controls you own as root:

  • Commission per tier — Rising 22%, Pro 18%, Elite 12% (defaults). Change at Settings → Payout Methods.
  • Hold period — days between sale and payout eligibility. Default 7. Lower means faster payouts and more chargeback risk.
  • Auto-approve threshold — payouts under this amount skip manual review. Default ₦250,000.
  • Instant payout — Elite mentors can withdraw in < 30 min for a 1.5% fee.
Ledger replay 
# Recompute a month of accruals without touching production.
knotwork ledger replay \
  --from 2026-03-01 \
  --to   2026-03-31 \
  --dry-run

Security Hardening Root-only

The five controls that matter most — and how to verify each one.

Root
  1. Enforce MFA for every admin. Non-negotiable. Configure at Settings → Security. TOTP or hardware key only — no SMS.
  2. Restrict admin IPs. Add your office and VPN ranges to the allowlist. Test with a non-listed device before saving.
  3. Rotate API keys quarterly. Command Center logs every rotation. Rotate during low-traffic windows and notify integrators 24h ahead.
  4. Review stale admins monthly. Any admin with no login in 90 days should be demoted or removed. Two currently flagged.
  5. Run a pen test twice a year. Last external test was 12 days ago; grade A. Next is scheduled for September.
Security posture score The score in your profile card (currently 92/A) is computed daily from MFA coverage, password age, IP allowlist drift, API key age, and open CVEs. Anything below 80 triggers a Slack ping to the security channel.
Audit current posture 
# Dump the daily posture report to stdout.
knotwork security posture --verbose

# Sample output
MFA coverage       100%   # all admins enrolled
Stale admins        2     # no login in 90d
API key age        41d    # rotate at 90d
Allowlist drift     0     # no changes
Open CVEs          0
Grade              A (92/100)

API & Integrations

Programmatic access to everything Command Center can do.

Key required

The Command API mirrors the admin UI one-to-one. Every endpoint that requires a scope lists it in the response headers. Rate limits are 600 req/min per key, burstable to 1,200 for 10 seconds.

curl · list pending payouts 
curl -H "Authorization: Bearer $KW_KEY" \
     https://api.knotwork.io/v2/payouts?status=pending
Idempotency keys Every POST to /v2/payouts accepts an Idempotency-Key header. Reuse the same key for retries — we'll return the original response instead of double-paying.

Troubleshooting

Common issues and their fixes.

Email worker queue is backing up

Check the task queue depth in the health dock. If it's above 25, the worker pool is saturated. Scale it from Integrations → Workers or temporarily lower the batch size.

Replication lag over 500ms

Happens during large exports. It self-resolves within a minute. If it persists, check the read replica IO in the health dock and open a ticket.

Admin locked out after IP change

Any other root admin can temporarily disable the allowlist from Settings → Security. The lockout auto-expires after 15 minutes.

Payout stuck in "approved" state

The provider is throttling. Payouts stuck more than 2 hours should be cancelled and retried — the ledger reconciles automatically.
