Portfolio Review — Reflections on Architecture

Submitted by Tunde Kalu · Advanced React Patterns · Assignment 04

Introduction. Over the last three modules I've been rebuilding a mid-sized React application around the composition patterns covered in class. This reflection is not about code that works — it's about the decisions that made it easy to keep working. Specifically, I want to document where I chose compound components over prop drilling, where I introduced context, and where the abstraction cost more than it saved.

What changed. The original app had a single CardGrid component receiving a dozen boolean props. After the composition lesson I split it into Grid, Grid.Item, and Grid.Empty. Behaviour stayed identical, but the mental model became legible: each piece now has one reason to exist. This was the single biggest readability win and I would recommend it to anyone facing the same shape of problem.

Where it went wrong. I over-applied the pattern in the settings page. Four pieces of state, all local, all used once — and I still wrapped them in context. The result was a file with three layers of indirection that a colleague described as "clever for cleverness' sake." I've since reverted it, and the reversion taught me more about composition than the original refactor did.

Next steps. I want to move the design tokens into a single tokens.ts file and see if the same composition discipline applies at the styling layer. My instinct says yes, but I'd rather build it than assume it.

Closing thought. The course has been less about learning new APIs and more about learning to notice when I'm making a decision. That has been more valuable than any single technique.
